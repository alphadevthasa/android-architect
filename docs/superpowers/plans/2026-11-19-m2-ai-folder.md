# android-architect M2 (`.ai/` generator, index, refresh) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give any Android project a committed (or local-only) `.ai/` folder: generated knowledge, workflows, a vendored copy of the tool scripts, a local BM25 index, and a manifest with hashes. `refresh` re-assesses the project against a newer catalog and reports what changed. Rejected recommendations are remembered and not repeated. The CLI gains `init`, `refresh` and `update`.

**Architecture:** Everything stays zero-dependency Node ESM inside `skill/`, so the installed skill and the vendored `.ai/tools/` are the same folder shape. New libraries in `skill/scripts/lib/` do one job each: tokenizer and BM25 index, git access, hashing and manifest, knowledge rendering, the `.ai/` writer with file-ownership rules, workspace linking, ADR parsing, and refresh diffing. New thin entry scripts (`index.js`, `init-ai.js`, `refresh.js`, `ai-status.js`) print JSON for the agent. `bin/cli.js` forwards `init` and `refresh` to them.

**Tech Stack:** Node >= 20 (ESM, `node:test`, `node:assert/strict`, `node:fs`, `node:path`, `node:crypto`, `node:child_process` `execFileSync` for `git` only). No dependencies.

**Spec:** `docs/superpowers/specs/2026-11-19-android-architect-design.md` (sections 5.2, 5.7, 5.8, 5.9, 5.11, 5.12, 5.13 A/B where marked, 5.16 "Remember rejections", 7).

**Milestone scope.** M2 covers: `update`, the `.ai/` generator, the local BM25 index, workflows, workspace mode, `--local`, manifest + hashes, `refresh` with the recommendation diff, and rejected ADRs. It also covers a short list of M1 follow-ups (Task 10). Out of scope (later milestones): secret *content* redaction, gitignore-aware indexing, refusing on tamper (M3; M2 only records and reports hashes); `catalog-overrides` merging (M3, needs the strict override parser); `feature-map.md` scores, `components.md` generation, `fitness`, `lib-update` (M4); `run.config.json` and `runs/` (M5).

## Global Constraints

- All docs, prompts, templates and code comments are in English.
- Runtime: Node `>=20`, `"type": "module"`, **no `dependencies`, no `devDependencies`**, no install-time scripts. `npm test` keeps running under `test/helpers/no-network.mjs`.
- Scripts make **no network requests**. No `eval`, `new Function`, or dynamic `import()` of computed paths.
- The only child process is `git`, run with `execFileSync('git', [fixed args], { cwd })`, never through a shell. When `git` is missing or the directory is not a repo, code degrades (commit `null`) instead of throwing, except `--local`, which needs a repo.
- Writes happen only inside `<root>/.ai/`, in `<gitDir>/info/exclude` (with `--local`), and in the pointer files listed in Task 4. Every write path is resolved and checked to be inside `<root>` (or the declared workspace repo); a symlinked `.ai/` or a symlink inside it is refused, never followed.
- Never overwrite a user-owned file (ownership table in Task 4). Never modify an existing `AGENTS.md`/`CLAUDE.md` unless `--append-pointers` is given.
- File walking reuses `listFiles` from `lib/walk.js`: same ignored dirs, same secret-file skip list, no symlinks out of the root.
- Generated Markdown starts with exactly this header line: `<!-- generated: <YYYY-MM-DD> @ <commit or no-git>, catalog <catalogVersion>. Do not edit: refresh overwrites this file. -->`
- Every script that writes or timestamps takes an injectable `now` (`Date`) so tests are deterministic; output JSON keys are emitted in a stable order.
- `.ai/manifest.json` `schemaVersion` is `1`. `.ai/index/index.json` `schemaVersion` is `1`.
- Commit messages: conventional commits, **no `Co-Authored-By` or `Claude-Session` trailers** (user rule).
- Designer call (deviation from spec 5.12 path): vendored scripts live at `.ai/tools/scripts/*.js` with the catalog at `.ai/tools/catalog/`, so `catalog.js`'s relative `../../catalog/` keeps working. Workflows call `node .ai/tools/scripts/index.js`.
- Designer call: a generated `.ai/candidates.json` (deterministic candidate snapshot) is added to the spec 5.7 layout so `refresh` can diff candidates.

## Review Focus

1. Vendored scripts run inside a project that has no `package.json` or a CommonJS one. Without `"type": "module"` next to them, Node parses them as CommonJS and every workflow call fails. Expected: `.ai/tools/package.json` contains `{"type":"module","private":true}` and `node .ai/tools/scripts/index.js query x` works from the project root. Pinned in Task 4.
2. Running `init` twice, or `init` and then `refresh`, on a project where the user has edited `architecture-target.md`, an ADR, `conventions.md` or `roadmap.md`. Expected: those bytes are unchanged, and the result lists them as `kept`. Pinned in Tasks 4 and 7.
3. A project that is not a git repo, or a git repo with no commits yet. Expected: `commit` is `null`, the header says `no-git`, and `init` succeeds. `--local` in a non-repo exits 1 with a clear message. Pinned in Tasks 2 and 4.
4. A large tree: thousands of source files, very long lines and minified files. Expected: indexing finishes, skips files over 1 MB, ignores tokens shorter than 2 or longer than 40 characters, and `index.json` stays proportional (term counts, not raw text). Pinned in Task 1.
5. `.ai/` (or a file inside it) is a symlink pointing outside the project. Expected: `init`/`refresh` refuse with exit 1 and write nothing outside the root. Pinned in Task 4.

### Task 1: Local BM25 index (`index.js build|query`)

**Files:**
- Create: `skill/scripts/lib/tokenize.js`, `skill/scripts/lib/bm25.js`, `skill/scripts/lib/indexer.js`, `skill/scripts/index.js`
- Test: `test/tokenize.test.js`, `test/bm25.test.js`, `test/indexer.test.js`, `test/index-cli.test.js`

**Interfaces:**
- Consumes: `listFiles(root)`, `readLines(abs)` from `lib/walk.js`; `discoverModules(root, files)` from `lib/modules.js`.
- Produces:
  - `tokenize(text: string) -> string[]`: lowercase; split on non-alphanumerics; each identifier also split on camelCase and digit boundaries (`RetrofitClient` gives `retrofitclient`, `retrofit`, `client`); keep tokens of length 2 to 40; drop the stopwords `the a an and or of to in for is on with this that it be as by`.
  - `buildBm25(docs: {id, tokens: string[]}[]) -> { avgdl, df: Record<string,number>, docs: {id, len, tf: Record<string,number>}[] }`
  - `scoreBm25(model, queryTokens: string[], { k1 = 1.2, b = 0.75 }) -> {id, score}[]` sorted by score desc, then id asc, and only score > 0.
  - `buildIndex(root, { now, commit, catalogVersion }) -> Index`, where Index is `{ schemaVersion: 1, generatedAt, commit, catalogVersion, params: {k1, b}, avgdl, df, docs: [{ id, kind: 'source'|'gradle'|'doc', path, line, title, len, tf }] }`
  - `queryIndex(index: Index, query: string, { limit = 10, kind } = {}) -> {path, line, kind, title, score}[]` with `score` rounded to 3 decimals.
  - CLI: `node index.js build <root> [--out <file>]` (default out `<root>/.ai/index/index.json`) and `node index.js query "<terms>" [--index <file>] [--limit N] [--kind source|gradle|doc]` (default index `./.ai/index/index.json`), JSON on stdout. Exit 0 ok, 1 usage error, 2 missing or unreadable index / not a Gradle project.

Document units (designer call; spec 6 leaves the format to the builder):
- **source** (`.kt`, `.java`): one doc per top-level or nested `class|interface|object|enum class|data class|sealed class|fun` declaration, with `title` = the name and `line` = the declaration line. Tokens are the name, the file's package, the file's import lines, and the file name. A file with no declaration becomes one doc with `title` = the file name and `line` = 1.
- **gradle**: one doc per module build file, with `title` = the module path and `line` = 1. Tokens are dependency `group`/`name`/`alias` and plugin ids.
- **doc**: Markdown files under `.ai/knowledge/`, `docs/`, and the root `README.md`, split at heading lines (`#` to `###`), with `title` = the heading text and `line` = the heading line. `.ai/knowledge` is read even though `listFiles` ignores `.ai/`: walk that directory separately with the same rules.
- Skip any file larger than 1 MB. Store term counts only, never raw text.

### Task 2: git access, hashing, manifest

**Files:**
- Create: `skill/scripts/lib/git.js`, `skill/scripts/lib/hash.js`, `skill/scripts/lib/manifest.js`
- Test: `test/git.test.js`, `test/manifest.test.js`

**Interfaces:**
- Produces:
  - `headCommit(root) -> string|null`: `git rev-parse --short=7 HEAD`. Returns null when git is missing, the dir is not a repo, or there are no commits.
  - `gitDir(root) -> string|null`: absolute path from `git rev-parse --absolute-git-dir`.
  - `addToExclude(root, patterns: string[]) -> { added: string[] }`: appends missing lines to `<gitDir>/info/exclude` (creating `info/` if needed). It is idempotent and throws `Error('--local needs a git repository')` when `gitDir` is null.
  - `sha256File(abs) -> string` (hex); `hashTree(dir, base) -> Record<relPosixPath, sha256>` over regular files, sorted keys, with symlinks rejected (throws).
  - `MANIFEST_SCHEMA_VERSION = 1`; `readManifest(aiDir) -> Manifest|null` (throws `Error` on JSON error, or on `schemaVersion` greater than supported); `writeManifest(aiDir, m)`.
  - Manifest: `{ schemaVersion: 1, toolVersion, catalogVersion, generatedAt (ISO), commit, mode: 'committed'|'local', workspace: null | { role: 'hub'|'member', hub: relPath }, tools: Record<path, sha256>, managed: Record<path, sha256> }`. `tools` covers every file under `.ai/tools/`. `managed` covers the workflow files as last written by the tool (Task 4 uses it to detect user edits).

### Task 4: `.ai/` writer, `init-ai.js`, `ai-status.js`, `--local`, pointers

**Files:**
- Create: `skill/scripts/lib/aidir.js`, `skill/scripts/init-ai.js`, `skill/scripts/ai-status.js`
- Test: `test/aidir.test.js`, `test/init-ai-cli.test.js`

**Interfaces:**
- Consumes: Tasks 1 to 3 (`buildIndex`, `headCommit`, `gitDir`, `addToExclude`, `hashTree`, `read/writeManifest`, `renderKnowledge`, `renderReadme`), `detectStack`, `candidatePaths`, `loadCatalog`.
- Produces:
  - `writeAiDir(root, { now, local = false, appendPointers = false, workspace = null, toolVersion, skillDir }) -> { written: string[], kept: string[], conflicts: string[], pointers: {file, action: 'created'|'appended'|'present'|'needs-confirmation'|'skipped-local'}[], excluded: string[] }`. Paths are relative to root and sorted.
  - `skillDir` defaults to the directory two levels above `aidir.js` (the installed or vendored skill root). Templates come from `<skillDir>/templates/ai/`. Vendoring copies `<skillDir>/scripts/**` to `.ai/tools/scripts/` and `<skillDir>/catalog/**` to `.ai/tools/catalog/`, then writes `.ai/tools/package.json` = `{"type":"module","private":true}`.
  - `aiStatus(root, { toolCatalogVersion }) -> { ok: boolean, stale: string[], manifest: Manifest|null }`. `stale` reasons are `no-manifest`, `commit-moved` (HEAD differs from `manifest.commit`), `catalog-moved` (`toolCatalogVersion` differs from `manifest.catalogVersion`), and `tools-modified` (`hashTree(.ai/tools)` differs from `manifest.tools`; reported only, refusal is M3).
  - CLI `init-ai.js <root> [--local] [--append-pointers] [--workspace [paths...]]` prints the `writeAiDir` result as JSON. Exit 0 ok, 1 usage or refusal, 2 not a Gradle project. `ai-status.js [<root>]` prints `aiStatus` JSON and exits 0 even when stale (stale is information, not failure). It exits 2 when there is no `.ai/manifest.json`.

File ownership (the core rule of this task):

| Class | Paths | `init` / `refresh` behavior |
|---|---|---|
| generated | `README.md`, `manifest.json`, `candidates.json`, `knowledge/{stack-profile,architecture-current,module-map,dependencies,feature-map}.md`, `index/index.json` | always rewritten |
| tools | `tools/**` | always rewritten from the running skill; hashes recorded in `manifest.tools` |
| managed | `workflows/*.md` | written when missing or when the current hash equals `manifest.managed[path]`; otherwise the new version goes to `<path>.new` and the path is listed in `conflicts` |
| user-owned | `knowledge/architecture-target.md`, `knowledge/conventions.md`, `knowledge/components.md`, `knowledge/adr/**`, `migration/roadmap.md`, `recommendations.json`, `repos.json` after the first write | created only when missing, otherwise listed in `kept` and never touched |

`recommendations.json` is never created by the writer (the agent writes it during `setup`/`recommend`); when present it is listed in `kept`. `repos.json` is written by workspace mode only when missing.

Pointers:
- Committed mode: for each of `AGENTS.md` and `CLAUDE.md` at the root, create the file from `pointer.md` when it is missing (`created`). When it already contains the marker, report `present`. When it exists without the marker, report `needs-confirmation` unless `appendPointers` is set, in which case append the pointer block (`appended`).
- `--local`: never touch `AGENTS.md`/`CLAUDE.md` (`skipped-local`). Create the pointer in `CLAUDE.local.md`, or append it when the marker is absent. Add `.ai/` and `CLAUDE.local.md` to `.git/info/exclude`, and record `mode: 'local'`.

Safety: before any write, `lstat` `<root>/.ai` and every existing path to be written. Any symlink means refuse with `Error('refusing to write through a symlink: <rel>')`. Each target's `path.resolve` must start with `realpath(root) + sep`.

### Task 5: Workspace (polyrepo) mode

**Files:**
- Create: `skill/scripts/lib/workspace.js`, fixture `test/fixtures/workspace/hub-app/` (app module depending on `com.example.core:core-net:1.4.0`) and `test/fixtures/workspace/lib-core/` (module `core-net` with `group = "com.example.core"` and the `maven-publish` plugin)
- Modify: `skill/scripts/lib/aidir.js` (the `workspace` option), `skill/scripts/init-ai.js`
- Test: `test/workspace.test.js`

**Interfaces:**
- Consumes: `discoverModules`, `listFiles`, `writeAiDir`.
- Produces:
  - `publishedArtifacts(root) -> string[]` (`group:name`). For each module, `group` comes from `group = "x"` / `group 'x'` in the module or root build file, or from `groupId = "x"` in a publication. `name` comes from `artifactId = "y"`, else the module dir name. Only modules that apply `maven-publish` or `com.vanniktech.maven.publish` count. Unresolvable values are skipped.
  - `siblingRepos(hubRoot) -> string[]`: absolute paths of sibling directories (same parent) that contain `settings.gradle(.kts)` or a root `build.gradle(.kts)`, sorted, excluding the hub.
  - `linkWorkspace(hubRoot, repoPaths: string[], { confirmed: boolean }) -> ReposJson` = `{ schemaVersion: 1, hub: '.', repos: [{ name, path (relative to hub, posix), artifacts, confirmed }], links: [{ consumer, producer, artifact, version|null, file, line }] }`. Links are built by matching each repo's external deps (all modules) against every other repo's `publishedArtifacts`.
  - `init-ai.js --workspace a b` uses explicit paths with `confirmed: true`. A bare `--workspace` uses `siblingRepos` with `confirmed: false`. The hub's `.ai/` gets `repos.json` (user-owned after the first write) and `manifest.workspace = { role: 'hub', hub: '.' }`. Each member repo gets a thin `.ai/`: generated knowledge, index, tools, README, and `manifest.workspace = { role: 'member', hub: <relative path to hub> }`. Members get no target, ADRs or roadmap, and their README says those live in the hub.
  - Every repo path is resolved with `realpath`, must be a directory with build files, and must not be inside the hub (or the hub inside it). Otherwise exit 1.
