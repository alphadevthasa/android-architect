# android-architect M3 (Security) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the tool safe to point at any repository and make security part of its advice. Concretely:
- Secrets never reach `.ai/` or the index.
- Git-ignored files are skipped.
- Tampered vendored tools are detected against a trusted reference and refused.
- Instruction-like text planted in `.ai/` is reported.
- Project catalog overrides are merged safely.
- Audits get deterministic security findings plus known-vulnerable dependency versions.

**Architecture:** New single-purpose libraries in `skill/scripts/lib/`:
- `redact.js`: secret patterns.
- `integrity.js`: trusted tool verification.
- `injection.js`: instruction scan.
- `security.js`: Android security signals.
- `vuln.js`: version ranges.
- `overrides.js`: catalog override merge.

They plug into the existing pipeline: `detectStack` gains `profile.security`; `writeAiDir`/`buildIndex` redact before writing; `aiStatus`/`doctor` verify tools. No dependencies, no network.

**Tech Stack:** Node >= 20 ESM, `node:test`, `node:crypto`, `git` via `execFileSync` only.

**Spec:** `docs/superpowers/specs/2026-11-19-android-architect-design.md` §5.13 A, B, C; §5.12 (catalog overrides); §7 Done-means lines on secrets and tamper. Backlog: `docs/superpowers/m2-followups.md`.

**Out of scope (later milestones):** playbook security checklists (playbooks arrive in M4); `lib-update` ranking security updates first (M4; M3 only detects them); `npm publish --provenance` (M5).

## Global Constraints

- All docs, prompts, templates and code comments are in English.
- Node `>=20`, `"type": "module"`, **no dependencies, no devDependencies**, no install scripts; `npm test` keeps running under `test/helpers/no-network.mjs`.
- No network. No `eval`, `new Function`, or dynamic `import()` of computed paths. `git` only via `execFileSync('git', [fixed args], { cwd, input? })`, never a shell.
- Writes only inside `<root>/.ai/`, `<gitDir>/info/exclude`, and pointer files, through the existing guarded writer in `lib/aidir.js`.
- Redaction placeholder format is exactly `[REDACTED:<kind>]` (spec 5.13 B), kinds lowercase kebab-case.
- Never print, store, or quote a matched secret value in any output, error message, test failure message, or report. Tests assert absence with `includes` checks whose failure message does not echo the value.
- Catalog and override files are strict JSON (M1 designer call) validated against `schemaVersion: 1`.
- `profile.schemaVersion` stays `1`. New profile fields are additive (`security`).
- Commit messages: conventional commits, **no `Co-Authored-By` or `Claude-Session` trailers** (user rule).
- Designer call: overrides live in `.ai/catalog-overrides/*.json` (JSON, not the spec's YAML), the same as the catalog.

## Review Focus

1. A secret inside ordinary Markdown (`README.md`, `docs/setup.md`) or a Gradle `buildConfigField`. Expected: neither the value nor any distinctive token of it appears anywhere under `.ai/` (index included). Pinned in Task 1.
2. A project that is not a git repo, or one with tens of thousands of files. Expected: gitignore filtering is a no-op without git, and runs as one `git check-ignore --stdin` call (not one process per file). Pinned in Task 2.
3. Tools and `manifest.json` tampered together (an attacker updates both). Expected: verification against the installed skill still reports `modified`. Pinned in Task 3.
4. An override with a catastrophic regex such as `(a+)+$`, or a 5 000-character pattern. Expected: rejected with a file-prefixed error before any matching runs. Pinned in Task 7.
5. Security-signal false positives:
   - an exported launcher activity
   - `debuggable true` only in the `debug` build type
   - `allowBackup="true"` with `dataExtractionRules`
   - `Log.d` without sensitive words

   Expected: none of them is reported. Pinned in Task 5.

### Task 7: Project catalog overrides (`.ai/catalog-overrides/*.json`)

**Files:**
- Create: `skill/scripts/lib/overrides.js`, `skill/templates/ai/catalog-overrides/README.md`
- Modify:
  - `skill/scripts/lib/catalog.js` (export the per-entry validator for reuse)
  - `skill/scripts/lib/aidir.js` (create the overrides README as user-owned; use overrides for detection)
  - `skill/scripts/lib/refresh.js`
  - `skill/scripts/scan.js`, `skill/scripts/candidates.js` (load overrides when `<root>/.ai/catalog-overrides` exists, unless `--no-overrides`)
- Test: `test/overrides.test.js`

**Interfaces:**
- Produces:
  - Override file shape: `{ "schemaVersion": 1, "entries": [{ "dimension": "<id>", "entry": { …full catalog entry… } }], "status": [{ "dimension": "<id>", "id": "<entryId>", "status": "current|legacy|deprecated", "reason": "…" }] }`.
  - `loadOverrides(dir) -> { entries, status, files }`. It reads `*.json`, sorted, and skips `README.md`. Each error is prefixed with the file name, and the first error throws `CatalogError`.
  - `applyOverrides(catalog, overrides) -> catalog`. The result is a new catalog object with `entry()` working. It also gets `overridden: { added: string[], statusPinned: string[] }` and `catalogVersion: '<base>+overrides'`.
  - Safety rules for override entries:
    - The id must not exist in that dimension already, so overrides can only add (status pins are separate).
    - `detect.computed` is forbidden.
    - Every `detect.content[].regex` must pass `safeRegex(src)`: at most 200 characters, compiles without flags, and no nested quantifier. Reject when a group that itself contains `+` or `*` is followed by `+`, `*` or `{`.
    - At most 50 entries per file and 20 files.
